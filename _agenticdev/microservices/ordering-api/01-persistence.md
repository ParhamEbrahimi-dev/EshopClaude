# Ordering.Api — 01 — Persistence

**Status:** Not started

## Goal

Give Ordering.Api its own schema in `orderingdb` so orders can be stored. Order and OrderItem form one aggregate, and as with catalog-api/01, the entities, DbContext, AppHost reference and schema creation can only be checked together (the tables in pgAdmin), so they stay in one spec. Once merged, `ordering-api/02-create-order` can write orders, and `03`/`04` can read them.

## Context

- Ordering.Api today has only the placeholder `GET /` (returns `Ordering API is running.`) and the health endpoints from `MapDefaultEndpoints()`.
- Its csproj already references `Aspire.Npgsql.EntityFrameworkCore.PostgreSQL` (added in step 2a), so no package change is needed.
- The AppHost already declares `orderingdb` on the shared `postgres` server (`postgres.AddDatabase("orderingdb")`, not kept in a variable). The `orderingapi` resource has no reference to it yet.
- **Connection string:** it comes only from the AppHost. `WithReference(orderingdb)` injects the environment variable `ConnectionStrings__orderingdb`, and `AddNpgsqlDbContext<OrderingDbContext>("orderingdb")` reads it. There is no fallback in `appsettings*.json`, so running Ordering.Api without the AppHost fails at startup. That is intended.
- **Schema creation:** `Database.EnsureCreated()` at startup, with no EF migrations. Aspire creates the empty `orderingdb` database. `EnsureCreated()` creates both tables when the database has none and does nothing on later starts.
- **Naming:** EF Core defaults. Tables `Orders` and `OrderItems`, PascalCase columns. No naming-convention package.
- **Dates:** `CreatedDate` is a `DateTime` that Npgsql maps to `timestamp with time zone`. Npgsql only accepts `DateTimeKind.Utc` values for it, so later specs must write `DateTime.UtcNow`.
- The Postgres container has no data volume, so every `aspire run` starts from an empty server. That's why the restart check below restarts only `orderingapi`.
- Catalog.Api's equivalent (`CatalogDbContext`, `EnsureCreated()` in `Program.cs`) is the pattern to follow.

## Depends on

Nothing.

## Data model

Both tables live in `orderingdb`, schema `public`.

Entity `Order` maps to table `Orders`.

| Property | C# type | Column | Postgres type | Constraints |
|---|---|---|---|---|
| Id | int | Id | integer | PK, identity (generated by default) |
| BuyerId | string | BuyerId | text | NOT NULL |
| CreatedDate | DateTime (UTC) | CreatedDate | timestamp with time zone | NOT NULL |
| Total | decimal | Total | numeric(18,2) | NOT NULL |
| Items | List&lt;OrderItem&gt; | — | — | navigation only, initialised to an empty list |

Entity `OrderItem` maps to table `OrderItems`.

| Property | C# type | Column | Postgres type | Constraints |
|---|---|---|---|---|
| Id | int | Id | integer | PK, identity (generated by default) |
| OrderId | int | OrderId | integer | NOT NULL, FK → `Orders.Id`, ON DELETE CASCADE |
| ProductId | int | ProductId | integer | NOT NULL (no FK, since products live in `catalogdb`) |
| ProductName | string | ProductName | text | NOT NULL |
| UnitPrice | decimal | UnitPrice | numeric(18,2) | NOT NULL |
| Quantity | int | Quantity | integer | NOT NULL |

- Relationship: one `Order` has many `OrderItem`s, through `Order.Items` and `OrderItem.OrderId`. `OrderItem` has **no** navigation back to `Order`, which avoids JSON cycles when later specs return orders.
- EF's FK convention creates the constraint `FK_OrderItems_Orders_OrderId` and the index `IX_OrderItems_OrderId`. There are no other indexes, no max lengths and no other columns, Status included.

## Tasks

1. Add the `OrderItem` entity class to Ordering.Api, with the six properties from the Data model. Use non-nullable strings.
2. Add the `Order` entity class with the four columns from the Data model plus `List<OrderItem> Items { get; set; } = [];`. Use non-nullable strings.
3. Add `OrderingDbContext` with `Orders` and `OrderItems` sets. In `OnModelCreating`, set the precision of `Order.Total` and `OrderItem.UnitPrice` to 18,2, and configure `HasMany(o => o.Items).WithOne().HasForeignKey(i => i.OrderId).OnDelete(DeleteBehavior.Cascade)`.
4. In Ordering.Api `Program.cs`, register the context with `builder.AddNpgsqlDbContext<OrderingDbContext>("orderingdb")`. After `builder.Build()`, create a scope, resolve the context and call `Database.EnsureCreated()` before the app starts listening.
5. In `AppHost.cs`, keep the `orderingdb` resource in a variable (`var orderingdb = postgres.AddDatabase("orderingdb");`) and add `.WithReference(orderingdb).WaitFor(orderingdb)` to the `orderingapi` registration. Don't change other resources.
6. Build, run, and go through every Definition of Done check.
